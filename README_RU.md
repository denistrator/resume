# Денис Белевцов — резюме

[English](README.md) | Русский

Персональный сайт-резюме Senior Magento Frontend Architect, эксперта по Hyvä и инженера
по производительности. На сайте представлены профессиональный опыт, навыки, достижения
и контактная информация на английском, русском и украинском языках.

## Возможности

- Переключение языка с сохранением выбора в браузере.
- Светлая и тёмная темы с учётом системных настроек и ручным переключением.
- Адаптивная вёрстка резюме и стили для печати.
- Загрузка PDF на всех трёх языках.
- Интерактивные сведения о результатах TOEFL и копирование электронной почты.

## Технологии

Сайт собирается в статические HTML, CSS и JavaScript. Настроенная для проекта система сборки
TARS 1.15.1 использует Gulp 4, Handlebars, SCSS, PostCSS/Autoprefixer, Babel и Terser.
Браузерные скрипты написаны на обычном JavaScript и объединяются из файлов компонентов.
Для размещения готового сайта не нужны сервер приложения или база данных.

## Локальная разработка

Требуется Node.js **20 или новее**. В процессе публикации используется Node 20.
Выполняйте команды из корня репозитория:

```bash
npm ci
npm install -g tars-cli --ignore-scripts
tars dev --lr
```

Устанавливайте TARS-CLI, только если он ещё не доступен. Он предоставляет зависимости
сборщика, которых нет в локальном списке пакетов. Проект уже инициализирован.

Откройте [localhost:3004](http://localhost:3004). BrowserSync обслуживает каталог `dev/`
и перезагружает страницу при изменении исходников. Порт можно изменить через `BROWSERSYNC_PORT`.

| Команда | Результат |
| --- | --- |
| `tars dev --lr` | Сборка для разработки, отслеживание файлов и BrowserSync |
| `tars dev` | Сборка для разработки и отслеживание файлов без BrowserSync |
| `tars build-dev` | Однократная сборка для разработки в `dev/` |
| `tars build` | Готовый сайт в `builds/` со ссылками на обычные CSS/JS |
| `tars build --min` | Готовый сайт с минифицированными CSS/JS; используется в CI |
| `tars build --release` | Минифицированная сборка с хешами в именах CSS/JS |
| `tars start check-public-repository` | Проверка содержимого индекса Git на отдельные типы конфиденциальных файлов и шаблоны учётных данных |

## Структура проекта

```text
markup/
  pages/index.html              Композиция страницы
  components/                   Шаблоны, стили, браузерные скрипты и данные компонентов
  static/
    scss/entry/main.scss        Точка входа стилей
    scss/vars.scss              Переменные тем и типографики
    img/                        Изображения и исходные SVG
    misc/                       Файлы для корня сайта, включая PDF
tars/                          Задачи сборки, вспомогательные функции и отслеживание файлов
docs/                          Документация проекта
tars-config.js                 Режимы сборки и пути
plugins-config.json            Настройки плагинов
.github/workflows/deploy.yml    Сборка и публикация
```

`dev/` и `builds/` — генерируемые каталоги. Вносите изменения в исходники, а не в результаты
сборки.

## Обновление резюме

Редактируйте содержимое в `markup/components/<component>/data/data.js`. Переводимые поля
содержат значения `en`, `ru` и `uk`; для общих строк можно использовать объект с единственным
ключом `default`. При сборке из этих файлов создаётся `translations.json`. Исходный HTML
содержит английский текст, а переключение языка выполняется браузерными скриптами.
Правила данных и шаблонов описаны в [руководстве по локализации](docs/i18n-pattern.md).

Разметка разделов и обработчики взаимодействий находятся в каталогах компонентов.
Подключайте SCSS компонентов в `markup/static/scss/entry/partials/_components.scss`,
а значения тем задавайте в `vars.scss`. Браузерные скрипты компонентов автоматически
включаются в текущую сборку с объединением файлов.

PDF-резюме в `markup/static/misc/media/` поддерживаются отдельно от содержимого сайта.
При изменении резюме обновляйте каждую языковую версию: сборка копирует PDF, но не создаёт их заново.

## Проверка изменений

Перед отправкой изменений исходников выполните сборку для публикации:

```bash
DISABLE_NOTIFIER=1 tars build --min
```

Просмотрите журнал задач и файлы в `builds/`. При изменении интерфейса также проверьте
в браузере переключение языка, сохранённые настройки, выбор темы, управление с клавиатуры,
мобильную вёрстку, предварительный просмотр печати и ссылки на PDF.

Автоматизированных тестов нет; `npm test` — заглушка, завершающаяся с ошибкой. Линтинг
не включён в обязательные проверки сборки. Сборка для публикации проверяет **содержимое индекса Git**
на отдельные риски публичного репозитория; изменения вне индекса и неотслеживаемые файлы
не проверяются. Подробные проверки и решение проблем описаны в
[руководстве по разработке](docs/development.md).

## Публикация

При отправке изменений в `master` или ручном запуске workflow сайт собирается командой
`tars build --min`, после чего содержимое `builds/` публикуется в Cloudflare Pages и GitHub Pages.
Для Cloudflare нужны секреты репозитория `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID`,
а также переменная `CLOUDFLARE_PROJECT_NAME`. Настройки публикации и известные ограничения
описаны в [документации по эксплуатации](docs/operations.md).
